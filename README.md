# Apex Sim

A deterministic open-wheel racing simulator written in Rust, with a live
browser dashboard. Draw a circuit in your browser, run a full qualifying
weekend, and race it — safety car, DRS, fuel load, tyre temperatures, crashes
and all. Every race replays **bit-identically** from its run log.

```
cargo run --release -- serve --cars 20 --laps 12 --seed 42
# dashboard: http://127.0.0.1:8080
```

## What's in the box

- **A real physics core** — 250 Hz fixed-timestep simulation: engine, brakes,
  tyre grip circle, slip, lockups, mass-sensitive acceleration (fuel is
  physics), per-corner speed limits derived from track curvature.
- **A race, not just a lap** — rolling formation lap, standing lights, pit
  stops with refuelling (stop time scales with fuel added), tyre wear and
  temperature, mechanical DNFs, driver-error spins, contact damage,
  yellow flags, a safety car that is a real car on the map, blue flags,
  DRS zones derived from the circuit shape.
- **Full race weekends** — solo-run qualifying that sets the grid, or a
  single race; weather and race-director controls live from the dashboard.
- **A draw-anything track editor** — sketch corners on a grid in the
  browser, press *Save & race*, and the field lines up on your circuit. Only
  one law: the drawing must close into a loop. Figure-8s, hairpins tighter
  than the paint and 200 m kart loops all race. Tracks are plain JSON
  (Catmull-Rom smoothed centreline).
- **Determinism you can audit** — same seed + config = same race, on your
  machine and the CI's; every run writes a self-contained log that replays
  bit-exactly (state-hash checked by the test suite). A stewarding module
  records incidents as replayable case files.
- **Headless tournaments** — batch many seeds/processes from one spec,
  with per-platform reproducibility semantics and a Docker image.
- **UDP telemetry out** — the sim publishes its state on the 2025 packet
  layout (`m_packetFormat = 2025`, port 20777) that popular telemetry
  tooling consumes; three independent community decoders parse it with zero
  disagreement (see `apexsim/docs/udp_telemetry_spec.md`).
- **An optional local-LLM strategy advisor** — point it at an Ollama
  endpoint and a model of your choice suggests pace/pit/tyre calls for one
  car, legality-checked by deterministic rules. Off by default; the sim
  never needs it.
- **A training gym** — an imitation-learning pipeline (dataset → ONNX
  policy) with parity and latency gates. Built, measured, and deliberately
  not enabled in races; the docs say why.

## The grid

Eleven fictional teams, two cars each, tuned via a human-editable JSON file
(`apexsim/teams.json`): Vortex, Aurora, Falcon, Meridian, Titan, Juniper,
Cobalt, Zenith, Everest, Sable, Polaris. Each team differs in engine, top
speed, brakes and tyres; a seeded per-driver form delta varies driver pace,
so teammates' cars are identical but no two drivers are. `--field classic`
restores the identical-cars mode.

All car liveries are **original, procedurally generated art**
(`tools/make_liveries.py`) — re-running the script reproduces the committed
sprites byte-for-byte.

## Repository layout

```
apexsim/           the engine crate: physics, race engine, weekend orchestrator,
                   weather, telemetry, sound, tournaments, stewarding, server +
                   dashboard, training gym, radio, and 28 gate-test suites
tools/             make_liveries.py (sprite generator), gym_train.py /
                   train_lib.py (policy training)
artifacts/phase12/ training evidence: exported policy.onnx, parity/latency/
                   comparison reports (the 22 MB dataset is regenerated by
                   the training script, not committed)
HOW_TO_RUN.md      setup and usage for humans
HOW_TO_RUN_AI.md   the same, written to be executed by an AI agent
```

`apexsim/README.md` is the detailed manual.

## Quick start

```bash
git clone <this repo>
cd apex-sim/apexsim
cargo test --release                       # 249 gate tests
cargo run --release -- race --cars 20 --laps 5 --seed 42   # headless race
cargo run --release -- serve --cars 20 --laps 12 --seed 42 # dashboard
# open http://127.0.0.1:8080 — Editor button draws a circuit, Save & race runs it
```

The same seed and config always produce the same race, and every recorded
run replays bit-identically — that invariant is what the gate suites
protect. Build output goes to a target dir outside the workspace
(`apexsim/.cargo/config.toml`, gitignored) so cloud-sync folders never fight
the compiler.
